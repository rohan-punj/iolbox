CORRESPONDING SOURCE FOR REDISTRIBUTED DEBIAN PACKAGES
======================================================

The iolbox macOS archive (iolbox-macos-arm64.tar.gz) redistributes a set of
Debian binary packages, used by the `native-arm64` profile to translate
x86_64 binaries inside the Lima guest and to provide the amd64 runtime those
binaries link against.

All of them are redistributed BIT-FOR-BIT UNMODIFIED as published by the
Debian Project. iolbox claims no copyright in them and has not patched,
rebuilt, trimmed or repackaged them.

The authoritative list of exactly what shipped -- package, version,
architecture, SHA-256 and filename -- is the MANIFEST file next to this one.


HOW THE SOURCE IS PROVIDED
--------------------------
The complete corresponding source for every package listed in MANIFEST is
published by the iolbox project as a release asset accompanying this archive:

    iolbox-macos-arm64-corresponding-source.tar.gz

It is available from the same iolbox release page you obtained this archive
from, for as long as this release is offered. It contains, for each source
package below, the Debian .dsc, the upstream .orig tarball, and the Debian
packaging tarball -- everything needed to rebuild these binaries.

That bundle is assembled by packaging/macos/guest-assets/fetch-corresponding-source.sh
in the iolbox source tree, which verifies every component against the
checksums in Debian's own signed .dsc files.

If you obtained this archive without that source asset, you may also obtain
the identical source directly from Debian at the URLs below, or by writing to
the iolbox project.

BINARY vs SOURCE VERSIONS
-------------------------
Three entries above intentionally show a source version that differs from the
binary version. These are NOT errors and must not be "corrected":

  binfmt-support   binary 2.2.2-7+b1                    <- source 2.2.2-7
  zlib1g           binary 1:1.3.dfsg+really1.3.1-1+b1   <- source 1:1.3.dfsg+really1.3.1-1

    The "+bN" suffix denotes a binNMU: a binary-only rebuild performed by
    Debian's build daemons against updated build dependencies, with NO change
    to the source. There is no separate "+bN" source package, and requesting
    one returns 404. The corresponding source is the un-suffixed version.

  libc6            <- source glibc
  libgcc-s1        <- source gcc-14
  gcc-14-base      <- source gcc-14
  libssl3t64       <- source openssl
  openssl-provider-legacy <- source openssl
  libzstd1         <- source libzstd
  zlib1g           <- source zlib
  libpipeline1     <- source libpipeline

    Debian source packages routinely build binaries under different names.


LICENCE TEXTS
-------------
notices/ contains, for each source package above, Debian's machine-readable
(DEP-5) copyright file taken verbatim from /usr/share/doc/<package>/copyright
inside the packages themselves. Those files carry the per-file copyright
attribution and identify each file's licence.

DEP-5 copyright files REFERENCE licence texts at /usr/share/common-licenses/
rather than embedding them, because on an installed Debian system the
base-files package provides that directory. This archive is not an installed
Debian system, so the referenced texts are shipped in full at:

    notices/licenses/

covering GPL-1, GPL-2, GPL-3, LGPL-2, LGPL-2.1, LGPL-3, Apache-2.0, Artistic,
BSD, CC0-1.0, GFDL-1.2, GFDL-1.3, MPL-1.1 and MPL-2.0.

Read notices/<source>.copyright together with notices/licenses/<NAME>: the
first tells you which licence applies to which file, the second is the
licence itself.


ALTERNATIVE ACCESS
------------------
These exact versions remain permanently available from Debian's snapshot
archive, regardless of what the current Debian release serves:

    https://snapshot.debian.org/

On a Debian 13 (trixie) system with deb-src entries enabled:

    apt-get source qemu-user-static
    apt-get source binfmt-support
    apt-get source libc6
    ...and so on for each source package listed above.
