actions on THAT node until it completes; show a per-node lock/progress state.

Files: `app/src/lib/labStore.svelte.ts`, `app/src/lib/nodes/{IolNode,VpcsNode,
NodeActions}.svelte`, `app/src/lib/components/CanvasInner.svelte`
(buildNodeMenuItems ~L678, buildSelectionMenuItems ~L733), optionally
`Palette.svelte`/`TopBar.svelte`.

Design:
- Add `nodeLocks = $state<Record<number, { action: string; startedAt: number }
  | null>>({})` to `LabStore`.
- Set the lock at the ENTRY of `startNode`/`stopNode`/`wipeNode`/`duplicateNode`
  (labStore ~L643–L790). Guard: if `nodeLocks[id]` already set, no-op the new
  action (that IS the lock).

  for that id arrives (~L296). For wipe/duplicate (RPC-ack only), clear when the
  awaited call resolves/rejects. Add a **60s safety timeout** so a lost event
  can't wedge a node permanently.

  - NodeActions: disable/hide action buttons while `isLocked`; show a small
    spinner + the pending action name.
  - Context menu + bulk selection menu: disable the relevant items when locked
    (bulk item disabled if ANY selected node is locked).
  - Node face (`IolNode`/`VpcsNode` `.face`): render a lock/progress overlay
    (spinner or progress ring near the `.led`) while locked. Reuse existing
    `--state-*` tokens + `led-pulse` idiom; both Bench and Glass themes.

## WS2 — Network Watcher: fix + directional per-protocol + packet-type subtypes

**Root cause (confirmed):** fabric `link.stats` omits `ProtosDir`
(`supervisor/internal/server/stats.go:98`) and only carries `Protos` while a
bridge capture runs; the frontend `watcherStore.matchFor()`
(`app/src/lib/watcherStore.svelte.ts:157`) hard-gates on `protosDir` → renders
nothing. The per-packet-type sub-discriminators in the reference screenshots
(BGP OPEN/UPDATE/NOTIF/KEEPALIVE; ICMP Echo-Req/Echo-Reply/Unreachable/
TTL-Exceeded; OSPF/EIGRP types) were **never implemented**.

### WS2-backend (supervisor/ only)

- **Extend classification to (label, subtype):** add subtype decoding to
  `internal/relay/classify.go` via cheap fixed-offset peeks. Keep the existing
  `Classify(frame) (label, tagged)` signature working (bcap + others call it);
  add a sibling e.g. `ClassifyDetailed(frame) (label, subtype string, tagged
  bool)` and have `Classify` delegate. Subtypes (at least):
  - ICMP: echo-request, echo-reply, unreachable, time-exceeded, redirect,
    other (peek type byte; you already split PING vs ICMP).
  - BGP: open, update, notification, keepalive, route-refresh (TCP :179; peek
    the BGP message-type byte after the 16-byte marker + length — guard against
    segmentation: only when the header is present in-frame).
  - OSPF: hello, db-desc, ls-request, ls-update, ls-ack (IP proto 89, packet
    type byte).
  - EIGRP: hello, update, query, reply, request (IP proto 88, opcode byte).
  - ARP: request, reply (optional).
  Guard every peek with length checks; unknown → subtype "" (omit).
- **Restore TRUE direction (per endpoint):** the user chose full
  per-direction. tcpdump-on-bridge can't attribute source, so add an
  **always-on, header-only, per-endpoint-tap classifier** for fabric links
  (behind `//go:build linux`, with an `_other.go` stub). Suggested approach: an
  in-process `AF_PACKET` raw socket bound to each endpoint tap, using the
  `PACKET_OUTGOING` sll_pkttype to split node→bridge (ingress) vs bridge→node,
  classifying each frame with `ClassifyDetailed`, accumulating per
  `(endpointIdx, label, subtype)`. Must be efficient (read headers only, bounded
  buffer), must NOT spawn per-link external processes, must NOT regress the
  always-on fps/bps glow, and must tear down cleanly on lab.stop / link.remove /
  teardownFabric. Reuse endpoint→tap mapping from `fabricLinkTapDevs`
  (`fabric_linux.go`). If AF_PACKET raw sockets need a privilege the non-root
  dev box lacks, gate behind the same sudo/root check the fabric mgr uses and
  degrade gracefully (aggregate, no direction) with a logged note — but the
  appliance runs the supervisor as root, so the always-on path is the target.
- **Emit contract:** extend `protocol.LinkStatsData` (verbs.go ~L305):
  - `ProtosDir map[string][2]float64` — now POPULATED for fabric links
    (`[fpsFromEp0, fpsFromEp1]` per label). Endpoint order == doc
    `endpoints[0]/[1]` order (FloatingEdge relies on this).
  - NEW `ProtosSubtypeDir map[string]map[string][2]float64 json:",omitempty"` —
    label → subtype → `[ep0,ep1]` fps.
  - Keep `Protos` for back-compat.
- Tests: table-driven `ClassifyDetailed` cases with crafted frames per subtype;
  keep existing classify tests green.
- **src/dst IP + port filters:** P1/best-effort. TRUE per-flow filtering needs a
  per-link flow table (src,dst,proto,port → count) which is a larger data model.
  If time allows, add a bounded flow-tuple counter to the per-tap classifier and
  a `flows` field; otherwise leave the UI inputs (WS2-frontend) present but
  clearly marked/deferred and DO NOT fake it. Document whichever you choose.

**Goal:** on-demand canvas overlays that show students how STP / OSPF / EIGRP /

### WS5a — painter BACKEND (supervisor/ only)

- **Console command runner:** generalize the mechanism `config.extract` already
  uses to drive the IOL console (consoleHub) into a reusable "run one exec `show`
  command on node N, return raw output" helper (enable/`terminal length 0`
  handling, bounded timeout, strip the echoed command + prompt). Do NOT open a
  second console owner that fights webconsole — reuse the hub/replay path
  config.extract uses.
- **New verb(s):** `painter.stp`, `painter.ospf`, `painter.eigrp`, `painter.bgp`
  (or one `painter.collect {proto, dest?}`), each: run the needed `show`
  commands on the relevant running nodes, PARSE IOS 17.x output, return a
  structured, canvas-mappable result. Results are keyed by **(nodeId,
  interface)** and/or (nodeId) so the frontend maps directly onto link
  endpoints (link endpoints already carry interface names like `e0/0`).
- **Per-protocol parse targets:**
  - **STP** (`show spanning-tree`): root bridge id + whether THIS node is root;
    per-port role (`Root|Desg|Altn|Back`), state (`FWD|BLK|LRN`), cost, priority;
    for a blocked/alternate port, a student-readable **reason** ("received a

  - **OSPF**: `show ip ospf neighbor` (DR/BDR per segment, adjacency state),

  - **EIGRP**: `show ip eigrp topology <dest>` (successor + feasible successors,
    FD/RD), `show ip route eigrp` for the winning next-hop.
  - **BGP**: `show ip bgp <prefix>` (best-path marked `>`, and the tiebreak
    reason — weight/local-pref/AS-path length/origin/MED/eBGP>iBGP/… — like the
    PNetLab BGP waterfall).
- **Dest selection:** routing verbs take a destination (prefix / node loopback /
  nodeId → resolve to an address). Return the per-hop winning next-hops so the
  frontend can highlight the path edges.
- Parsers must be tolerant (version banners, wrapped lines, `% ` errors → empty
  result, not a crash). Table-driven Go tests with realistic IOS 17.x fixture
  blocks per protocol. stdlib-only; new package e.g. `internal/painter`.

## WS6 — NAT egress-capability gating (honest NAT on ICMP-less runtimes)

**Why:** the QEMU **launcher** uses user-mode **slirp**, which terminates ICMP
— so `ping`/`traceroute` to the internet CANNOT work through the NAT node there
(DHCP + outbound TCP still work). Every other runtime (WSL2 behind WinNAT,
bridged VMware/OVA, LXC/native/Docker on a real host) has a real kernel + real
host NAT/bridge and DOES pass ICMP/traceroute. Students shouldn't silently hit a
dead ping; the NAT node should say so on slirp.

### WS6-backend (supervisor/ only; disjoint from WS5b — may run in parallel)

- **Auto-detect egress capability at startup.** QEMU user-mode slirp has a fixed
  signature: guest DHCP addr `10.0.2.15`, default gateway `10.0.2.2`, DNS
  `10.0.2.3`, net `10.0.2.0/24`. Detect it from the routing table / primary
  iface (default route via `10.0.2.2`, or primary addr in `10.0.2.0/24` with the
  slirp gateway). Match → egress is ICMP-limited; else assume full.
- Add a `-egress auto|slirp|routed` flag (default `auto` = detect) as an explicit
  override/escape hatch. The shipped systemd unit stays on the default (`auto`);
  detection carries it. No launcher/unit changes required.
- **Hello contract:** add `Egress string \`json:"egress"\`` to `HelloResult`
  (`protocol/verbs.go`) with values `"slirp"` (ICMP/traceroute to internet NOT
  available through NAT) or `"routed"` (full). Optionally a short human `egressNote`.
  Populate it in the hello handler. Keep everything else unchanged.
- Detection must be cheap, best-effort, and never fail startup (unknown →
  `"routed"`, the permissive default, so non-launcher runtimes are unaffected).
  Linux detection behind `//go:build linux` with an `_other.go` stub.

### WS6-frontend (after WS5b + WS6-backend commit)

- Read `hello.egress` into the store (`supervisor.ts` HelloResult →
  `labStore`). Expose e.g. `labStore.egress`.
- On the **NAT node** (kind `nat`, rendered by `VpcsNode.svelte`) and its palette
  entry: when `egress === "slirp"`, show a small warning badge + tooltip
  "DHCP & TCP only — no ping/traceroute on this runtime (QEMU slirp). Use the
  bridged VMware/OVA appliance or WSL2 for real internet.", and a subtle greyed
  treatment on the NAT glyph. **Keep the node fully functional** (DHCP/TCP labs
  still valid) — badge/inform, do NOT disable it. Both Bench and Glass themes.
- When `egress !== "slirp"` (routed/unknown) the NAT node renders normally with
  no badge. Do not touch non-NAT nodes.

## v0.3.0 backlog (NOT this batch — captured for later)

### Console unification — single arbitrated shared session (PNetLab-style)
**DONE (v0.3.0, all 5 phases landed) — see `docs/v0.3.0-console-unification.md`
for the full design, resolved decisions, and phase-by-phase implementation
record.** Summary below kept for historical context.

Today console access is several independent telnet clients dialing the node's
loopback console port (web bridge self-dials, native OS-telnet dials, and the
painter's `runShow` / `config.extract` dial). The `consoleHub` already fans
*output* out to many subscribers, but each client negotiates telnet
independently — the shape behind the old negotiation CPU-spin (patched via RFC
1143 Q-method, not structurally removed) and the painter-vs-open-console
contention risk. Proposal: make the hub the **sole owner** of the one connection
to each node's pty and route EVERYTHING through it — web, native (as a hub
subscriber, hub owns the telnet listener), and programmatic drivers — as
subscribers, with light **input arbitration** (a programmatic writer takes a
short input turn: emit `show …`, read echo→prompt, release; interactive typing
briefly queued). Benefits: (1) retires the multi-negotiator CPU-spin class at
the root (one negotiated connection, subscribers get decoded bytes); (2) makes
`runShow`/painter/config-extract safe (arbitrated writer, not a racing telnet
client) — directly de-risks the painter; (3) teaching win — students SEE the
painter's `show` commands scroll in their own console; (4) true simultaneous
web+native on one session. Trade-offs: input arbitration is the hard part
(output fan-out already exists); two humans co-typing still garbles (inherent to
one physical console); native-as-subscriber needs the hub to own a telnet
listener. Pairs naturally with the painter (first heavy programmatic console
consumer). Scope: a modest evolution of the existing hub, not a rewrite.

### Launcher optional bridged-uplink mode — DROPPED (2026-07-04)
Rationale: real ICMP/traceroute already works on the two non-slirp runtimes —
the **VMware/OVA appliance** (VMware NAT forwards ICMP echo + TTL-exceeded, or
bridged mode) and **WSL2** (WinNAT does the same). Only the QEMU launcher's
slirp can't, and WS6 already badges the NAT node there to say so. Since anyone
needing traceroute has two working paths, a launcher-specific tap-windows6 +
Windows-bridge/ICS uplink (third-party driver + admin + wired Ethernet, big
cross-machine test tail) isn't worth it. Guidance: **traceroute labs → bridged
VMware/OVA appliance or WSL2, not the launcher.** (Caveat: this rests on how
VMware NAT / WinNAT handle ICMP — both do — rather than an empirical traceroute
run; verify once on a real appliance/WSL2 if certainty is wanted.)

### Persist image-fingerprint cache across launcher boots
`snapshot=on` discards the guest ImageDir each boot, so the launcher re-uploads
+ re-registers (re-hashes) every IOL image every launch — slow under TCG. Could
persist `.image-cache.json` (size/mtime-keyed) on the Windows side and restore
it so `image.register` skips the re-hash. (v0.2.1 mitigated the *symptom* — the
register timeout — but the repeated hash cost remains.)
