## WS1 — Per-node action lock + progress/lock indicator

**Goal:** issuing start/stop/wipe (and duplicate) on a node locks all sibling
actions on THAT node until it completes; show a per-node lock/progress state.

Files: `app/src/lib/labStore.svelte.ts`, `app/src/lib/nodes/{IolNode,VpcsNode,
NodeActions}.svelte`, `app/src/lib/components/CanvasInner.svelte`
(buildNodeMenuItems ~L678, buildSelectionMenuItems ~L733), optionally
`Palette.svelte`/`TopBar.svelte`.

Design:
- Add `nodeLocks = $state<Record<number, { action: string; startedAt: number }
  | null>>({})` to `LabStore`.
- Set the lock at the ENTRY of `startNode`/`stopNode`/`wipeNode`/`duplicateNode`
  (labStore ~L643–L790). Guard: if `nodeLocks[id]` already set, no-op the new
  action (that IS the lock).
- Release: for start/stop, clear in `handleEvent` when the `node.state` event
  for that id arrives (~L296). For wipe/duplicate (RPC-ack only), clear when the
  awaited call resolves/rejects. Add a **60s safety timeout** so a lost event
  can't wedge a node permanently.
- UI: `isLocked = $derived(labStore.nodeLocks[nodeId] != null)`.
  - NodeActions: disable/hide action buttons while `isLocked`; show a small
    spinner + the pending action name.
  - Context menu + bulk selection menu: disable the relevant items when locked
    (bulk item disabled if ANY selected node is locked).
  - Node face (`IolNode`/`VpcsNode` `.face`): render a lock/progress overlay
    (spinner or progress ring near the `.led`) while locked. Reuse existing
    `--state-*` tokens + `led-pulse` idiom; both Bench and Glass themes.
- Console open/native-console are client-side/no-WS → do NOT lock.

## WS2 — Network Watcher: fix + directional per-protocol + packet-type subtypes

**Root cause (confirmed):** fabric `link.stats` omits `ProtosDir`
(`supervisor/internal/server/stats.go:98`) and only carries `Protos` while a
bridge capture runs; the frontend `watcherStore.matchFor()`
(`app/src/lib/watcherStore.svelte.ts:157`) hard-gates on `protosDir` → renders
nothing. The per-packet-type sub-discriminators in the reference screenshots
(BGP OPEN/UPDATE/NOTIF/KEEPALIVE; ICMP Echo-Req/Echo-Reply/Unreachable/
TTL-Exceeded; OSPF/EIGRP types) were **never implemented**.

### WS2-backend (supervisor/ only)

- **Extend classification to (label, subtype):** add subtype decoding to
  `internal/relay/classify.go` via cheap fixed-offset peeks. Keep the existing
  `Classify(frame) (label, tagged)` signature working (bcap + others call it);
  add a sibling e.g. `ClassifyDetailed(frame) (label, subtype string, tagged
  bool)` and have `Classify` delegate. Subtypes (at least):
  - ICMP: echo-request, echo-reply, unreachable, time-exceeded, redirect,
    other (peek type byte; you already split PING vs ICMP).
  - BGP: open, update, notification, keepalive, route-refresh (TCP :179; peek
    the BGP message-type byte after the 16-byte marker + length — guard against
    segmentation: only when the header is present in-frame).
  - OSPF: hello, db-desc, ls-request, ls-update, ls-ack (IP proto 89, packet
    type byte).
  - EIGRP: hello, update, query, reply, request (IP proto 88, opcode byte).
  - ARP: request, reply (optional).
  Guard every peek with length checks; unknown → subtype "" (omit).
- **Restore TRUE direction (per endpoint):** the user chose full
  per-direction. tcpdump-on-bridge can't attribute source, so add an
  **always-on, header-only, per-endpoint-tap classifier** for fabric links
  (behind `//go:build linux`, with an `_other.go` stub). Suggested approach: an
  in-process `AF_PACKET` raw socket bound to each endpoint tap, using the
  `PACKET_OUTGOING` sll_pkttype to split node→bridge (ingress) vs bridge→node,
  classifying each frame with `ClassifyDetailed`, accumulating per
  `(endpointIdx, label, subtype)`. Must be efficient (read headers only, bounded
  buffer), must NOT spawn per-link external processes, must NOT regress the
  always-on fps/bps glow, and must tear down cleanly on lab.stop / link.remove /
  teardownFabric. Reuse endpoint→tap mapping from `fabricLinkTapDevs`
  (`fabric_linux.go`). If AF_PACKET raw sockets need a privilege the non-root
  dev box lacks, gate behind the same sudo/root check the fabric mgr uses and
  degrade gracefully (aggregate, no direction) with a logged note — but the
  appliance runs the supervisor as root, so the always-on path is the target.
- **Emit contract:** extend `protocol.LinkStatsData` (verbs.go ~L305):
  - `ProtosDir map[string][2]float64` — now POPULATED for fabric links
    (`[fpsFromEp0, fpsFromEp1]` per label). Endpoint order == doc
    `endpoints[0]/[1]` order (FloatingEdge relies on this).
  - NEW `ProtosSubtypeDir map[string]map[string][2]float64 json:",omitempty"` —
    label → subtype → `[ep0,ep1]` fps.
  - Keep `Protos` for back-compat.
- Tests: table-driven `ClassifyDetailed` cases with crafted frames per subtype;
  keep existing classify tests green.
- **src/dst IP + port filters:** P1/best-effort. TRUE per-flow filtering needs a
  per-link flow table (src,dst,proto,port → count) which is a larger data model.
  If time allows, add a bounded flow-tuple counter to the per-tap classifier and
  a `flows` field; otherwise leave the UI inputs (WS2-frontend) present but
  clearly marked/deferred and DO NOT fake it. Document whichever you choose.
